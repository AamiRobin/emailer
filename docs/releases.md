# Release channels & runbook

Emailer ships two release channels. Both are built by the same GitHub
workflow (`.github/workflows/release.yml`), which triggers on any `v*` tag
and publishes immediately — there is no manual draft step.

| Channel | Tag shape | GitHub release | In-app update endpoint |
| --- | --- | --- | --- |
| **Beta** | `vX.Y.Z-beta.N` (any semver prerelease) | marked **pre-release** | `…/releases/download/channels/latest-beta.json` |
| **Stable** | `vX.Y.Z` (no suffix) | the repo's **latest** release | `…/releases/download/channels/latest-stable.json` |

The app checks the channel the user picked in **Settings → Updates**. Both
endpoints are static URLs on a perpetual `channels` release that the
workflow overwrites on every build (`--clobber`), so a channel switch is a
manifest swap — no reinstall. GitHub's "latest" release excludes
prereleases, which is what keeps the stable channel pinned to plain tags.

## Cutting a release

The app version must equal the tag exactly (the workflow derives the
release from the app version), so always bump first:

```bash
npm run version:set -- 0.2.0-beta.1   # or 0.2.0 for stable
git commit -am "chore: release v0.2.0-beta.1"
git tag v0.2.0-beta.1
git push origin main v0.2.0-beta.1
```

The workflow then builds Windows (NSIS + portable exe), macOS Apple
Silicon + Intel (DMG), and Linux (AppImage + deb), publishes the release
with generated notes, and uploads the signed updater manifest to the
`channels` release.

**Promoting a beta to stable** is just the stable tag of the same version:
`npm run version:set -- 0.2.0`, commit, tag `v0.2.0`, push. Beta users
receive it on their next check (the beta manifest then points at the
stable build only after the next beta — until then beta users keep the
beta; this is the standard trade-off, and fine at this scale).

## Update signing

Update artifacts are signed with a minisign keypair generated by
`bunx tauri signer generate`:

- **Private key:** lives only in the repo secrets
  (`TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`) and
  in the maintainer's local `.tauri-signing/` directory (gitignored).
  **Back it up** — losing it means shipped apps can no longer verify an
  update, and rotating it requires every user to reinstall.
- **Public key:** committed in `src-tauri/tauri.conf.json`
  (`plugins.updater.pubkey`). The updater refuses any manifest whose
  signature does not match.

## macOS / Windows install notes

- macOS builds are ad-hoc signed (`APPLE_SIGNING_IDENTITY: -`). First
  launch needs right-click → **Open**, or
  `xattr -cr /Applications/Emailer.app`, until the project has a Developer
  ID certificate.
- Windows SmartScreen may warn on the unsigned installer; "More info →
  Run anyway" is expected for now.
- The Windows portable exe requires the Microsoft Edge WebView2 runtime
  (preinstalled on Windows 11).
